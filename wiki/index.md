## Components

- [Ableton Push 1](pages/ableton-push.md) — Rhino drives the original Push itself on its User port and keeps all four of its ports from the engine; the pads are translated into a scale or a Drum Rack's bank on the MIDI thread and play like any keyboard, and the buttons and encoders become Rhino's commands, never a track's MIDI.
- [App shell and control bar](pages/app-shell.md) — The shell under app/ - Application in a Main.cpp of about 200 lines, MainWindow, and MainComponent across six units holding the control bar, the docked browser, the single lower pane, the 30 Hz timer that polls what the engine never broadcasts, and the modal loading screen a long command runs behind.
- [Arrangement view](pages/arrangement-view.md) — The timeline UI, one class across fifteen files, that previews every drag locally, re-reads only the tracks the model marked changed, pins the return tracks and the main row under the scrolling lanes, and leaves panel decisions to the shell.
- [Audio clip editor](pages/audio-clip-editor.md) — Edits one audio clip's own gain, pan, pitch, fades, mute and reverse as clip properties, with one undo step per knob drag.
- [Bounce to New Track](pages/bounce-to-new-track.md) — Ctrl+B renders the selection as a span (a clicked clip is its own span), a track or a group to an audio file on a new track directly under its source and mutes the source in the same undo step, by Live 12's rules - a track before its fader, a group after its bus, a time selection cut at its edges - a slice per frame behind a cancellable loading screen.
- [Browser and library preview](pages/browser.md) — A six-section library rail, Drums first, whose rows leave only by drag, with samples and drum presets auditioned through a second audio callback.
- [Built-in devices](pages/built-in-devices.md) — Every device Rhino ships, what each one is and where its source lives, with Utility's details and the pitfalls the devices share.
- [Clip slots, the DJ consoles' cells](pages/clip-slots.md) — Each track's clip slots, one per scene, are the cells a DJ console's clips grid shows; what the model guarantees about them, and the clip launcher that first showed them, removed on 2026-10-11.
- [Computer MIDI keyboard](pages/computer-keyboard.md) — Plays notes from the typing keyboard into the MIDI input with Forge's exact key mapping, so arming and recording need no special case.
- [Content library](pages/content-library.md) — Samples, device presets, drum kits and drum presets live as files under library/, found at runtime by ContentLibrary, audio stored with Git LFS, nothing compiled in.
- [DJ deck engine](pages/dj-deck-engine.md) — How a deck plays inside the booth's engine - a plan and a read, loops that wrap by modulo, crossfaded jumps, quantised landings at exact frames, sync on the master's tempo, stable slots, a port that carries a deck's audio and notes into a track of the song and back, and material handed back only when the audio thread is done with it.
- [DJ view and the booth](pages/dj-view.md) — Up to six CDJ-style decks either side of a DJM-style mixer, run by Rhino's own engine as a second audio callback, playing files or a track's own cells heard live through the track's chain.
- [Device catalog](pages/device-catalog.md) — The one table of Rhino's devices that the browser, drop targets, rack menu, engine registration and instrument rules all read.
- [Device presets (.rnd)](pages/device-presets.md) — A device's settings saved as a .rnd file by parameter id, filed under the device in the browser, dragged to add the device already set, and loaded or saved from its name bar.
- [Device rack and device editors](pages/device-rack.md) — The Device View strip that shows a track's chain and its per-device faces, the rebuild rule that shapes how a face is written, and the timer that follows automated knobs.
- [Drum Rack](pages/drum-rack.md) — A pad on every MIDI note, addressed by note, each a sample or one of eight synthesised drums with six automatable controls; the face shows a bank of sixteen beside a map of all 128 and opens 1024 x 720 in a window of its own that floats above the main window, and kits (.rdk), drum presets (.rdp) or dropped samples fill it.
- [Drum Rack sample editor](pages/drum-rack-sample-editor.md) — How a Drum Rack sample pad plays its file (one-shot, classic or slice), kept as undoable pad content rather than automatable controls, cut at transients or into equal parts, and spread onto pads of their own.
- [Forge ARP plate, slots and waterfall](pages/forge-arp-plate.md) — The painted plate between Forge's keys and note guide - a lamp, four slot buttons that swap the five pattern panes' 25 parameters through ARPSLOT nodes on the state tree, a door to the overlay, and a well where every note the voices play falls through the floor, a held one leaving a trace that hangs and brightens.
- [Forge arpeggiator](pages/forge-arpeggiator.md) — Stands in front of the voices, hands notes back through two callbacks, keeps four pattern slots, and opens as an overlay from a plate between the keys and the note guide.
- [Forge editor (panel)](pages/forge-editor.md) — One Editor class across twenty files builds the panel from declared modules and decides what is visible in one place.
- [Forge engine (Core)](pages/forge-engine.md) — The header-only voice engine that allocates sixteen voices, modulates per voice per sample and scales the output by 0.28.
- [Forge filter](pages/forge-filter.md) — Two per-voice filters of 34 types in six families, each source routed into either, both or neither and FILTER 1 optionally in series into FILTER 2, shown as one two-bank module, with the drawn response and the audio read from the same header.
- [Forge LFOs](pages/forge-lfos.md) — Each of the six LFOs is a NORMAL shape, a PATH across the pad with X and Y outputs, or an S&H staircase, read FORWARD, REVERSE or PING-PONG, and the panel draws it from the one function the voice reads.
- [Forge MIDI learn](pages/forge-midi-learn.md) — Right-click learn binds a controller's knobs and pads to any control; bindings are kept per machine in MidiMap.xml, not in patches.
- [Forge mixer and effects racks](pages/forge-mixer-and-fx.md) — The MIX tab's ten channels and two busses, and three eight-slot effects racks of nine types that run on the summed voices, each slot printing its readings and fed meters by the engine once a block.
- [Forge modulation: matrix, envelopes, LFOs and macros](pages/forge-modulation.md) — Thirty matrix slots, eight on the table until a patch needs more, route envelopes, LFOs, macros and performance sources to any continuous control, the envelopes' own knobs and the oscillators' OCT and FINE included, per voice, in the knob's own range.
- [Forge noise module](pages/forge-noise.md) — A per-voice noise oscillator with nineteen generated sources in six families, each a colour through a character stage.
- [Forge note guide](pages/forge-note-guide.md) — A view-only chord and scale helper - a door on the keyboard shelf that names what the guide is set to and opens a NOTE GUIDE overlay on ENV and LFO, as the ARP plate does, where a root is picked on an octave of keys, a chord and a scale from button grids, and a readout spells their notes and degrees; the piano colours them, and every C carries its octave.
- [Forge oscillators and wavetables](pages/forge-oscillators.md) — Three identical oscillators, each reading its own band-limited wavetable, plus the table editor, the table field that browses tables/ by title rather than by parameter, NEW and SAVE, and the audio-thread hand-off.
- [Forge preset browser and bank](pages/forge-preset-browser.md) — LOAD opens a browser over Forge's modules that lists the player's own bank in Documents/Rhino Forge/Presets, filled with the factory set on first use, beside the machine's Serum 2 and Vital libraries, read only, all listed from file heads alone on a lister thread that shows a folder's last listing while it re-reads only the files that changed.
- [Forge preset import (Serum 2 and Vital)](pages/forge-preset-import.md) — Forge opens Serum 2 and Vital presets by converting each one into a Forge state tree through one PatchWriter and loading that tree like a .forgepreset; anything Forge lacks is left out with one warning each, and all 75 local Vital presets and all 626 Serum 2 factory presets convert.
- [Forge presets and state](pages/forge-presets-and-state.md) — Presets and host state carry one tree, which also holds the patch's name, author, style, notes and conversion warnings; every arriving patch goes through applySavedState; a preset of another format version is refused, and within a version everything is reconciled.
- [Forge spectral oscillator](pages/forge-spectral.md) — An oscillator mode that resynthesises a loaded sample with a phase vocoder, so pitch and scan position move independently (M16).
- [Forge themes and Merli](pages/forge-themes.md) — Every Forge chrome colour is a token in ui/ForgeTheme.h with a value per theme; the theme is a machine setting the Editor reads once, as its first member, before any control is built, and Merli, the second theme, redraws the chrome as fur and matte plates over the identical layout.
- [Forge warp](pages/forge-warp.md) — Two warp stages per oscillator, 43 modes in nine families, OSC modes able to read either other oscillator, chained through one read function and anti-aliased by duller tables.
- [Hosting Forge in Rhino](pages/forge-hosting.md) — How Rhino finds, loads and talks to the Forge VST3, and what does and does not cross the plugin boundary.
- [Keyboard velocity curves](pages/keyboard-velocity-curves.md) — A velocity curve per MIDI keyboard port, kept per machine; a port set to anything but Linear is read by Rhino itself, bent on the MIDI thread and delivered to All Ins and a "<port> (curved)" stand-in, because Tracktion cannot rewrite a note on its way in.
- [Mapped parameters, an external plugin's rack](pages/mapped-parameters.md) — An external plugin's rack is a chosen list of its parameters, kept on the device by the plugin's own parameter ids, Forge's nine most-played controls at first, and grown by MAP, which opens the plugin's window and puts every control touched there on the rack to automate.
- [Mixer](pages/mixer.md) — One mixer, drawn in the arrangement's track cards, with a VolumeAndPanPlugin, a level meter behind it and post-fader sends to the return tracks in each track's channel strip, mute and solo that silence only a track's output and what it sends, and the master volume for Main; a DJ deck takes its track ahead of the channel strip, and a fader drag cannot be undone yet.
- [Note editor (StepGrid)](pages/note-editor.md) — Edits the open MIDI clip's notes in steps under a bars-and-beats ruler, on rows of one height that a short pane scrolls rather than squeezes (a drum clip's only its rack's assigned keys), snapped unless Alt is held, with a draw mode, a right-button menu that never erases, a Ctrl+E chop set by dragging, a preview through the clip's own track, an insert line that pastes land on and a velocity lane, tied closely to Session by its caches.
- [Note editor drum rows](pages/note-editor-drum-rows.md) — On a drum clip the note editor's rows are its Drum Rack's assigned keys plus the keys its notes are on, mapped through lines, moved row to row, held still under a gesture, opened on the rack's bank and scrolled like a piano clip's.
- [Note editor velocity lane](pages/note-velocity-lane.md) — A lane under the note editor's rows, modelled on Live 12's velocity editor, with a marker for every note of the clip in MIDI 1-127, edited by drag, draw-mode stroke, marquee and keys, each gesture one undo step announced once at its end.
- [Pattern presets](pages/pattern-presets.md) — The eleven built-in one-bar patterns, each a set of notes plus the instrument and patch that play them, and what dropping one does to a track.
- [Playhead rendering](pages/playhead.md) — Draws both playheads every display refresh from the audio graph's own position, repainting two narrow strips whose painters skip everything else, with a Direct2D fix.
- [Project files (.rhinoedit)](pages/project-files.md) — A .rhinoedit is the Tracktion edit's XML plus Rhino's own properties, saved from a snapshot on a worker and opened off-thread.
- [Recording and the count-in](pages/recording.md) — Arms tracks, not inputs, lets each take win the ground it lands on, and counts in with Rhino's own click while the playhead stands still.
- [Return tracks and sends](pages/return-tracks.md) — Live's return tracks - an ordinary track fed by an engine aux bus, kept with the other returns at the foot of the stack and drawn pinned between the scrolling lanes and the main row - and one post-fader send per return at the end of every other track's chain, set from -inf to 0 dB on a knob under the card's name; a new document has A Delay and B Reverb, wholly wet, fed nothing.
- [Rhino Arp](pages/rhino-arp.md) — A built-in MIDI arpeggiator with beat or millisecond scheduling and a dedicated five-area rack face.
- [Rhino EQ](pages/rhino-eq.md) — Eight-band EQ whose drawn curve comes from the same coefficients as the audio, over a spectrum computed off the audio thread.
- [Rhino FM](pages/rhino-fm.md) — A four-operator FM synth in eight routings, written on the device SDK, whose modulation index is checked against Bessel functions and whose face shows its operators as tabs, its carriers in a routing diagram, and the waveform it makes.
- [Rhino Forge](pages/forge.md) — Rhino's independent wavetable and spectral synth, a VST3 and standalone app built from one JUCE AudioProcessor.
- [Rhino Tune](pages/rhino-tune.md) — Vocal pitch correction with YIN tracking and PSOLA shifting, real reported latency, and correction smoothed on the offset.

## Concepts

- [Clips never overlap](pages/clip-placement.md) — The clip that just arrived wins the ground it lands on, and one function, Session::makeRoomForClip, enforces it for every path.
- [Device chain order](pages/device-chain-order.md) — A track's plugin list is its signal chain - the hidden DJ input (on a return track followed by its aux return), MIDI FX, instrument, audio FX, the hidden DJ output, a channel strip of Utility, fader and meter whose Utility sits on a different side of the fader on starter and added tracks, then one send per return - so the first visible device is plugin 1, or 2 on a return; how every add and every drag keeps that order.
- [Pointer and selection rules](pages/pointer-and-selection.md) — One pointer vocabulary for the arrangement and the note editor, written once as shared predicates in SelectionInput.h.
- [Region editing](pages/region-editing.md) — The lanes have one selection, a region - a span of time across a run of tracks, made by clicking a clip's header or sweeping the lanes - and copy, cut, paste, duplicate, delete, the arrow nudge and a drag by any clip header inside it all act on that rectangle; on a focused card the keys move whole tracks.
- [Serum 2's preset format](pages/serum-2-preset-format.md) — A .SerumPreset is a JSON metadata header followed by one zstd frame of CBOR; this page records the layout and the knob laws Forge's importer relies on, measured by the GPLv3 serum2vital project and taken from it as facts, not code.
- [The main track](pages/main-track.md) — The main output row is the edit's master plugin list, addressed as track index trackCount() so track-indexed calls need no sentinel, pinned last under the returns with a card and a colour of its own.
- [Track and clip colours](pages/track-and-clip-colours.md) — Every new track, return and the main row are born with a palette colour; a clip wears its track's colour until C gives it its own rhinoClipColour.
- [Track kinds: audio and MIDI](pages/track-kinds.md) — Every track is audio or MIDI from creation; one property records it, one call reads it, and the model refuses mismatched content.

## Decisions

- [A deck's bounce renders on a worker against a copy of the document](pages/dj-bounce-on-a-copy.md) — Superseded on 2026-10-12, when decks stopped bouncing - how a track or group bounced to a DJ deck rendered on the booth's worker from a snapshot copy of the edit, kept for what it found about copies of a document, relative sources and the renderer.
- [A long command runs in slices behind a modal screen](pages/long-commands-run-in-slices.md) — A command that must render the live document (Bounce to New Track and Export WAV, so far) stays on the message thread but works a slice per frame behind the shell's modal LoadingScreen, so the window draws and can cancel while nothing can edit the document under it.
- [A group is an ordinary bus track](pages/group-is-a-bus-track.md) — A group's bus is a plain te::AudioTrack kept in getAudioTracks(), so every track-indexed path reaches it with no second code path.
- [A return is an ordinary track at the foot of the stack](pages/return-track-at-the-foot-of-the-stack.md) — A return track is a plain te::AudioTrack in getAudioTracks(), kept with the other returns under every other track and over the main row, and every track carries a send to every return from the moment either exists; taking returns out of the track list and making sends on first use were rejected, and since 2026-10-25 only the arrangement draws the returns pinned beside the main row.
- [A track's kind is fixed when it is made](pages/track-kind-fixed-at-creation.md) — A track declares audio or MIDI at creation, nothing dropped on it changes that, and every mismatched drop is refused in the model.
- [Content is files, never compiled in](pages/content-is-files.md) — Samples and other content live as files under library/ and are found at runtime; only fonts, app icons and two tiny SVG glyphs are embedded.
- [DJ decks play live through the track's chain](pages/dj-decks-play-live-through-the-track.md) — A deck on a track plays the track's own cells through the track's live devices, by two hidden devices every track carries from its creation, so every edit is heard at once; why the devices are permanent, what it costs, what a review of it fixed, how Tracktion's real graph proves it, and the bounce, the bind-time devices and the message-thread note injection it rejected.
- [Forge is an independent VST3](pages/forge-is-an-independent-vst3.md) — Why Forge is its own JUCE plugin project, hosted by Rhino through Tracktion's external-plugin wrapper rather than built in.
- [Forge's engine splits into headers only](pages/forge-engine-headers-only.md) — Forge's engine splits into headers so renderSample stays inlined without LTCG, while the panel splits into .cpp files freely.
- [Forge's FX strips are per-type plans in a pure header](pages/forge-fx-strip-plans.md) — Each rack slot is laid out by its effect type's own strip plan, from one pure function in ui/ForgeFxStrips.h that the editor, the painter and the layout test all call; the slot's identity card is its bypass, and a filled slot's type is never changed in place.
- [Forge's FX slots declare generic parameters](pages/forge-fx-slots-have-generic-parameters.md) — Every rack slot exposes the same twelve anonymous parameters, because a host's parameter list is fixed when the plugin is built.
- [Forge's Processor includes nothing under ui/](pages/forge-processor-includes-no-ui.md) — Since 2026-10-25 src/ForgeProcessor.h includes no header under ui/; the theme choice is free functions in src/ForgeThemeSettings.h that the Editor runs as its first member, and the panel colour constants the state reads live in core/ForgePanelColours.h, so the Processor neither draws nor knows a theme exists.
- [No backward compatibility for .rhinoedit](pages/no-rhinoedit-back-compat.md) — Rhino owes older .rhinoedit documents nothing; a project that opens wrong is fixed in the current save and load path, not by a migration.
- [No track is special for being first](pages/pattern-track.md) — Rhino began as one pattern on one synth track; commit a04b407 retired every rule that singled out the first track, and each track's own chain now records what it plays.
- [One instrument per track](pages/one-instrument-per-track.md) — A track runs exactly one instrument; a new one replaces the old in place, and nothing may cache an instrument pointer.
- [The executable is RhinoDAW, not Rhino](pages/executable-named-rhinodaw.md) — The binary is RhinoDAW.exe because NVIDIA's driver profile for Rhinoceros 3D, keyed on Rhino.exe, corrupted the app's Direct2D repaints.
- [The native device standard](pages/native-device-standard.md) — Rhino's own devices are written on one SDK base, held to one conformance runner and given generated faces, with their presets as .rnd files; VST3 stays the format for outside instruments.
- [The source tree mirrors the layers](pages/source-tree-mirrors-the-layers.md) — Since commit b68fa0e (2026-10-13) native/src is laid out as app, model, ui/<view>, core/{dsp,dj,content}, devices and tests; an include is spelled from its target's root, files keep their class prefix, and a JUCE module for RhinoCore was rejected.
- [Tracktion Engine with a native JUCE UI](pages/tracktion-and-juce.md) — Rhino runs on Tracktion Engine with a hand-built JUCE interface, chosen in September 2026 over a custom engine, Qt Quick, WebView or Tauri.

## Conventions

- [Colours and typography](pages/colours-and-typography.md) — Rhino names chrome colours in Theme.h's palette and draws text in embedded Inter; Forge names its own as theme tokens in ForgeTheme.h and draws in four faces.
- [Dependency direction](pages/dependency-direction.md) — Knowledge flows one way in both products, UI to model to devices to core, every rule lives in the model so each UI path inherits it, and a lint in the geometry test keeps the views from reaching the engine behind Session.
- [Directories not to read](pages/off-limits-directories.md) — native/.deps and research/sources are not Rhino's code and are never searched; Tracktion signatures are checked in curated header snapshots, and a method body in the pinned commit on GitHub.
- [Documentation ownership](pages/documentation-ownership.md) — READMEs introduce and build the products; the wiki is the canonical home for engineering detail, decisions and gotchas.
- [Displays draw from the DSP](pages/displays-draw-from-the-dsp.md) — A curve on screen is computed by the same functions the audio runs, never from a second set of formulas, and tests hold the two together.
- [Git workflow](pages/git-workflow.md) — Focused, verified commits pushed at milestones; stage explicit paths since the user edits Forge in the same tree; never rewrite pushed history.
- [Hold ids, not pointers](pages/ids-not-pointers.md) — Anything kept beyond one call holds an id or a copy, never a raw engine pointer, because undo, moves, reloads and publishes free the object.
- [Keeping files small](pages/keeping-files-small.md) — Split a .cpp past about 600 lines or a second responsibility by defining one class across several translation units, not by inventing types.
- [Measure sound, don't read the DSP](pages/measure-sound-dont-read-dsp.md) — Claims about pitch, level or timbre are settled by rendering audio and measuring it by a route that cannot agree with the DSP by construction.
- [Real-time audio rules](pages/real-time-audio-rules.md) — The audio thread never allocates, locks, or touches files or UI; memory is sized at prepare and state crosses threads via atomics and queues.
- [Stored indices are append-only](pages/append-only-stored-indices.md) — Saved choice lists and parameter arrays are append-only, because inserting an entry silently changes what an old index means.
- [What a change costs the interface](pages/ui-cost-of-a-change.md) — Session announces every change synchronously to every listening panel, so a drag announces once, a hidden panel goes stale, a sync reads only the tracks the model marked, a frame reads only the controls it shows, painters skip what a repaint does not reach, and --profile-ui and --profile-stress measure it.

## Gotchas

- [A buffered child broke Forge's byte-identical paint](pages/buffered-child-breaks-pixel-stability.md) — Buffering the title plate's PresetPlate to an image made two pixels of another component differ between two fresh Forge panels under Direct2D and failed the theme suite's byte-for-byte check, so the plate is drawn unbuffered; run forge_theme after adding any buffered child. Since 2026-10-25 the committed tree fails that check by two pixels a shade apart with no buffered child to blame, on whichever curve or glow the layout puts them, because Direct2D draws the same path into a second bitmap a shade differently; chromeCacheSuite paints on a software image for that reason.
- [A build's --parallel does not cap the compiler](pages/build-parallel-does-not-cap-compiler.md) — Rhino's and Forge's build trees compile with /MP and no count, so cmake --build --parallel N limits only how many projects build at once and cl.exe runs a file per logical core; on the 16 GB second machine two Forge builds ended in GPU-driver blue screens, and /p:CL_MPCount=2 is the cap.
- [A CachedValue can lag its own ValueTree](pages/cachedvalue-lags-its-tree.md) — A ValueTree listener that reads a juce::CachedValue of the same property may run before the cache updates, so force the cache first; in Rhino the race failed only under parallel CTest.
- [A CTest SegFault may be a stack overflow](pages/stack-overflow-reports-as-segfault.md) — CTest reports a Windows stack overflow (0xC00000FD) as a bare SegFault; so far the cause was large objects on the stack in both test binaries and, once, a runaway recursion.
- [A Forge preset with no subPan loads its sub 3 dB hotter](pages/forge-presets-without-subpan-load-hotter.md) — Processor::migrated takes any state with no subPan PARAM for one saved before the mixer and multiplies subLevel and noiseLevel by the square root of two, so the 18 original factory presets, which never wrote subPan, load their sub 3 dB above what make-presets.py states; left as is on purpose, and every new preset writes subPan and noisePan.
- [A JUCE component listening to itself hears its own clicks twice](pages/juce-self-listener-hears-clicks-twice.md) — A component registered as its own mouse listener gets every event on itself twice, so every toggle on Rhino's device faces flipped on and straight back off; hear the children through a separate listener, and test clicks through real dispatch.
- [A JUCE drag finds its target in JUCE's window order, not the screen's](pages/juce-drop-target-follows-its-own-window-order.md) — A drag that may leave its window picks its drop target by juce::Desktop's own list of windows, reordered only when JUCE hears a window come to the front, so a window kept above another by the OS (an owned window) loses drops to the window beneath once that one is clicked; Rhino re-raises its floating windows whenever the main window comes forward.
- [A JUCE image is drawn at the last colour's opacity](pages/juce-image-draws-at-current-opacity.md) — juce::Graphics composites drawImage and its variants at the context's current opacity, which the last setColour set, so a kept layer pasted after a translucent colour comes out faded; Forge's FX picture cache greyed out every picture from its second frame on until commit 44e19bb set the opacity to 1 before the blit.
- [A JUCE parameter cannot print a value outside its range](pages/juce-parameter-text-clamps-to-range.md) — NormalisableRange::convertTo0to1 and convertFrom0to1 both clamp, and a parameter's getText formats the denormalised value, so text for a value past either end always prints that end; format an out-of-range value yourself or name the end.
- [A JUCE plugin's DLL is freed at the host's next PeekMessage](pages/plugin-dll-freed-at-next-peekmessage.md) — JUCE's Desktop hooks the message thread with the plugin's own module handle, so the host's FreeLibrary is not the last reference and the plugin detaches inside whatever next pumps messages, DestroyWindow or OleUninitialize; by then JUCE's GUI singletons are gone and only the plugin's C++ statics are left to run under the loader lock.
- [A juce::Button fires its click on a right-click too](pages/juce-button-fires-on-right-click.md) — juce::Button presses and clicks for any mouse button, so a key that carries a right-click menu also runs its left-click action unless mouseDown and mouseUp swallow the popup-menu press first, as the DJ console's DjPad does.
- [A juce::Path holding only a start point is empty](pages/juce-path-isempty-ignores-a-lone-point.md) — juce::Path::isEmpty() ignores startNewSubPath points, so a loop that asks it whether to start or continue a line starts a new subpath every time and strokes nothing; keep a flag of your own.
- [A layout that reads a child's preferred size must sync the child first](pages/sync-children-before-layout.md) — DjView laid itself out before syncing its mixer, so the layout read the mixer's width from the old strip count and a new deck's strip sat under the master section until the next resize; sync the children a layout measures first, and re-lay out when the measured size changes.
- [A new source file needs an explicit CMake configure](pages/cmake-does-not-reconfigure.md) — Both projects suppress CMake regeneration, so a file or a flag added to a CMakeLists is silently left out until you configure again.
- [A plugin's static Direct2D images deadlock NVIDIA's driver at unload](pages/plugin-static-images-deadlock-on-unload.md) — A juce::Image with static storage in a plugin is a Direct2D bitmap released by the DLL's detach under the loader lock, where NVIDIA's driver waits forever; four in Forge's UI froze RhinoDAW at shutdown, leaving it running with no window, until commit f2a972e (2026-10-22) moved them into JUCE's ImageCache.
- [A send ignores mute while muted tracks are processed](pages/send-ignores-mute-when-muted-tracks-process.md) — With shouldProcessMutedTracks true, Tracktion's default shouldProcessAuxSendWhenTrackIsMuted (true) never silences an aux send, so a muted or solo-excluded track kept feeding its returns; Rhino overrides it, and because the engine reads the answer only when it builds the graph, Session::followReturnSolo rebuilds the graph whenever the answer changes.
- [A track that feeds a bus renders nothing on its own](pages/bus-member-renders-nothing-alone.md) — Tracktion builds a track whose output names another track only as an input of that track, so a group member rendered alone renders nothing; Bounce to New Track points it at the default output and switches its fader off for the render only, outside the undo history.
- [An edit's project id names its temp folder](pages/edit-temp-folder.md) — Tracktion keeps an edit's cached renders in a folder named for its project id and purges it whenever an edit is built, so a second edit built from a document's state must not take the document's id; learnt from the DJ deck copies, removed on 2026-10-12.
- [App icons are baked at configure time](pages/app-icon-baked-at-configure.md) — JUCE turns the icon PNGs into an .ico at configure time, so editing the art and rebuilding still ships the old icon.
- [Build locks from MSBuild nodes and orphaned compilers](pages/orphaned-build-processes.md) — An object or source file that another process holds is usually another session's build, an idle MSBuild node or an orphaned cl.exe.
- [Editing only a scenario .inc does not rebuild the tests](pages/inc-edits-do-not-rebuild.md) — An edit to a workflow scenario alone has left the old test binary in place, so CTest passed a scenario that was never compiled.
- [Forge's tick repaints its live regions at 24 Hz](pages/forge-panel-repaint-cost.md) — Since 2026-10-25 Forge's editor tick repaints only its live regions - the ARP plate, each shown module's header band and display, the matrix and the rack, the table panel - and every control repaints itself when it changes; until then it repainted the whole panel every frame. What is drawn in a live region is still paid 24 times a second, and what moves on its own outside them is never redrawn.
- [JUCE's isBold() is false for SemiBold](pages/juce-isbold-misses-semibold.md) — juce::Font::isBold() matches only the whole word Bold, so a LookAndFeel keyed on it serves the Regular cut for SemiBold text.
- [JUCE's key codes are not constant expressions](pages/juce-keypress-codes-not-constexpr.md) — juce::KeyPress::upKey and the other named key codes are static const int members defined in a .cpp, not constexpr, so they cannot go into a static constexpr array; build a table of them at run time.
- [JUCE's rasteriser is not clip-invariant](pages/juce-rasteriser-not-clip-invariant.md) — A path's anti-aliased edge can come out differently under a different clip, so check a culled repaint against an unculled paint under the same clip, never against the whole paint.
- [juce::File::createOutputStream appends](pages/juce-output-stream-appends.md) — JUCE opens an existing file for output at its end, so rewriting a PNG or a render in place leaves the old content in front.
- [LNK1104 means a running binary holds the file](pages/locked-executable-lnk1104.md) — A link that fails with LNK1104 after every file compiled means a running RhinoDAW, DAW or Forge standalone holds the output; renaming the held binary, Forge's VST3 included, lets the link succeed while the holder runs on.
- [Offline renders that never return](pages/renders-that-never-return.md) — Five known causes make an offline render hang for good, a clip whose file is missing among them, and the Moved render timeout failure is usually just a busy machine.
- [One knob diameter for the whole Forge panel](pages/forge-knob-diameter-is-panel-wide.md) — Every ordinary knob takes the tightest cell's size, so crowding one module shrinks them all; the test meant to catch it cannot fail.
- [Profile paint on a software image](pages/profile-paint-on-a-software-image.md) — On Windows a plain juce::Image is a Direct2D bitmap whose context costs about 3 ms a paint whatever is drawn, so time painters on juce::SoftwareImageType() and repaint what the app really invalidates.
- [Tracktion's hosted device is silent until its start is dispatched](pages/hosted-device-silent-until-dispatched.md) — Driving Tracktion's real playback graph headless through its hosted audio device renders nothing, the transport not even moving, until te::DeviceManager::dispatchPendingUpdates runs the preparation the device's start posted to a message loop the test runners never dispatch.
- [Why a patch copied from Serum sounds different](pages/serum-patches-sound-different.md) — Check matrix polarity, PD warp depth, the filter's FREQ and the output stage before suspecting Forge's tuning or DSP.
- [Writing a clip's reverse switch moves its window](pages/writing-reverse-moves-a-clips-window.md) — Tracktion mirrors an audio clip's offset into its file on every write of isReversed, even writing off onto a new clip, so a trimmed copy jumped to the far end of its file; write such a property only when the value differs.
